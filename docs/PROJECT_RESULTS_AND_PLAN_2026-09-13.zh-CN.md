## 3. 研究成果与可成立的结论

### v1 / v2：可用性与正式终测

- v1 heldout100 注册单次为 70/100，另两次为 71/100、73/100。它与后续 v2 不是同一组比较，不能用这些数字推算版本提升。
- v2 完成 train150、dev100、test100 摄取，合计 **16,685 个会话、43,426 条记忆**。dev100 的五臂、三次重复共 **1,500 行**，依注册规则选定 `flat20 / two_stage_fallback`。
- v2 test100 完成一次性三臂终测，结果与执行源代码封存：

| 方法 | 正确率 | 中位回答上下文 token | 回答＋评分实际 token |
|---|---:|---:|---:|
| v2 记忆＋条件原文回退 | 72% | 574 | 159,458 |
| 整段历史 | 86% | 109,059 | 10,932,294 |
| naive RAG | 65% | 12,763 | 1,352,847 |

记忆/RAG 上下文按字符估算，全文使用 provider 输入 token，因此约 190 倍、22 倍是不同计量口径下的近似上下文比值，不能直接当账单节省。实际 usage 列不含共享抽取成本。v2 对 naive RAG 高 7 个百分点，但配对 `p=0.3368`，未建立稳定优势；全文高 14 个百分点，配对 `p=0.0043`。

v2 源会话命中为 94%，回答正确率为 72%；命中至少一个来源不代表全部答案证据齐全。28 个错误中，3 个未找到来源会话，14 个原文回退后仍错，11 个已有来源上下文仍错。这支持继续研究证据组合和回答过程，但不允许再用封存 test100 调参。

## 4. 本轮发现的关键问题与已修复事项

### 计数金标：当前最高优先级

原生成器将“记忆行数”当作集合成员数量，混入意图/偏好与已完成行为，还无法正确处理一行多个实体、多行同一实体、问句动词与范围矛盾。

目前有 **38 条模型建议，0 条人工裁定**。建议剔除 31、保留 7，使开发集 30 道题的成员从 149 降为 118，18 道答案发生变化；这只是暂定叠加层。它没有修改原始探针和隐藏划分。

依该层离线重读 v4.2：对照 **12/30**、候选 **7/30**，净差 −5，描述性聚类 p=0.125。不能将事后、模型修正的结果视为证明损害或替换原注册结论；接受这 38 条也仍不能解决实体计数单位问题。

已准备完整 38 条人工复核材料和空白决策 JSON，包含题目、成员、来源与模型建议，不展示两臂回答或成绩。由于模型建议可见，它不是完全盲审；人工应先按规则作独立判断，对争议项明确复核。
