# README 修改建议与本次落实

本次只处理图和文档。建议的核心是：README 先让读者理解项目、看懂已验证结果、成功运行一个入口；详细实现、实验沿革和动态研究状态各有一个明确入口。

## 已落实的结构调整

原来的中英文 README 各有三张长 Mermaid 图，实验沿革又有两套高度重叠的表。新结构为：

1. 项目一句话定位与演示说明。
2. 一张总览图和最短可运行步骤。
3. 简短设计说明，三张细节图折叠展示，链接完整六图图集。
4. 一个冻结最终结果表；v3 研究结果单独说明。
5. 接口及默认状态、限制、文档导航。

“一路是怎么走过来的”和“每个阶段，按顺序”合并到 [实验沿革](EXPERIMENT_HISTORY.zh-CN.md) / [English](EXPERIMENT_HISTORY.md)。保留已有未提交改动中的阶段记录与负结果，补充已存在的 v4 档案链接及 v3 审计限定。README 中不再重复两遍。

## 后续还建议怎么改

以下需要单独做的工作，这一轮没有实现：

| 优先级 | 具体改法 | 完成标准 |
|---|---|---|
| 高 | 为默认服务实现真实 `extract_turn` adapter 或明确提供批量导入入口，再增加“写入一句 → 搜索回来”的 README 示例 | 全新 store 中能运行；示例输出来自该命令；只配置声明过的依赖 |
| 高 | 把 README 结果表绑定到一个可验证的发布摘要，生成中英文相同数字 | 题集、臂、重复次数、准确率、usage、来源哈希一起变化；不手工拼接不同代结果 |
| 中 | 给估算 context 与实际 provider token 不同列名 | 三种 runner 的计量对象写清；不把任一比值直接叫作账单节省 |
| 中 | 将接口的全部字段和请求/响应示例集中到独立指南 | README 只留下入口和能力状态；字段与 Pydantic/OpenAPI 保持一致 |
| 中 | 给每个研究版本一个明确的状态与证据链接 | 区分“实现”“开发集测量”“冻结验证”“最终未见测试”，不使用含义模糊的“已上线” |
| 低 | 增加只检查 Markdown 链接和 SVG 可重建性的文档 CI | 不启动模型、不读封存行、不为了图的检查改变实验环境 |
