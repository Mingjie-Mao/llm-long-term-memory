# 项目报告

LLTM 从历史对话提取用户事实，保存原文出处与时间状态，为后续问题提供长期记忆。
实现见[架构](ARCHITECTURE.md)，完整实验口径见[评测说明](EVALUATION.md)。

## 设计与产品范围

```text
历史对话 → 抽取事实和出处 → 去重 → 重建时间状态 → SQLite＋向量索引
                                                ↓
问题 → 记忆语义检索＋用户原话检索 → 回答上下文 → 按需补回原文
```

两阶段抽取记录事实主体、属性、值、更新操作和来源。时间解析区分新增、替换、终止与并存，
保留历史版本，支持 `as_of(t)`。会话时间与事实时间分开，近似相对日期保留原表达和精度。
这些机制依赖正确的抽取与关联，不保证所有真实更新都被正确识别。

服务默认 t4 结合记忆和约 4,000 token 原话，按用户与时间窗口找证据，并标注相对日期。
记忆提供事实状态，原文保留精确数字、日期和措辞。调用方管理当前会话上下文；本项目不承担
企业 RAG 或当前会话工作记忆。

## 最新完整验收

2026-10-19，原 LongMemEval-S test100 的已暴露题集回归完成：同一 100 题，两组各三轮，
600 份回答和 600 份原金标评分通过完整性审计，注册验收为 PASS。

| 受测版本 | 三轮正确数／100 | 平均正确率 | 回答＋评分已记录 token |
|---|---|---:|---:|
| 同期旧 v2 | 70 / 68 / 68 | 68.67% | 476,864 |
| 限定范围 t4 候选 | 86 / 87 / 85 | **86.00%** | 2,465,965 |

模型未换，平均净增 17.33 个百分点；候选中位上下文为 6,254.5 token。提升伴随约 5.17 倍
的 token 工作量，不含已有抽取成本和服务未报告的失败用量。三轮是重复测量，仍只有 100 道
独立问题；本结果不是新的未见终测，也不等同于所有服务配置的准确率。

## 已确认的问题与负结果

- **抽取有损。** 冻结 v2 的 dev50 失败里，10/14 首先丢在抽取。带原文补回的后续版本，
  残余损失更多落在回答推理。来源会话命中不能证明关键事实已进入上下文。
  [分层归因](../results/failure-attribution-reconciliation.md)
- **批大小影响抽取，但依赖会话构成。** 特定 60 会话队列中，批 15 → 8 的具体信息召回
  为 37.3% → 64.9%；其他队列不复现同一效应量。保真度提升不等于答题提升。
  [批次实验](../results/batch-size-result.md) · [队列归因](../results/analysis/batch8-session-kind-attribution-v1.md)
- **出处改进未证明新的答题收益。** 出处 v2 回填提高定位准确率，但检查的变化题中，目标原话
  本已在 t4 上下文。[回填分析](../results/analysis/anchor-v2-backfill-v1.md)
- **确定性计算也可能选错条目。** 程序覆盖计数／日期答案的候选退步；只记录不覆盖的改动
  收益在噪声内，没有接入产品。[回答侧实验](../results/analysis/t4c-v1.md)
- **更新链仍会误关。** 时间关系判定在小标注集表现好，真实库回填却出现错误关闭和顺序依赖，
  已停止扩大。[实际库复查](../results/analysis/link-backfill-d1-dev100-reviewed-20261013.md)

因此不能把 86% 解读为证据覆盖、时间解释和条目选择三个问题均已解决。本轮原 test100
仍有错答，尚未对其重新逐题归因；开发集诊断与本轮结果应分别使用。

## 工程边界与下一步

SQLite 与 NumPy 索引采用单写进程方案，没有跨资源原子事务或多实例写入保证。
仓库中的 Demo 支持显式启用两阶段 LLM 抽取、t4 回答与证据检查，复用产品服务并注入 ONNX 编码器；
公开部署是否启用以页面状态为准，未启用或模型服务失败时不生成规则替代答案。

下一步先检查递归摘要的零调用可行性，再独立注册总成本与正确率对照。摘要生成、更新、
检索、原文补全和回答均计入成本，并按查询次数摊销；不能只以输入缩短宣称降本。
已知抽取与时间关系错误继续按首损分层处理，计划见[路线图](../research/ROADMAP.md)，
完整历史见[实验索引](../research/EXPERIMENT_INDEX.md)。
