# 项目进展：做了什么、存在的问题、接下来的计划

截至 2026-10-08。本文合并了此前分散的过程记录（10 月 1–7 日的计划、验收、修复、续作、问题清单和
9 月的仓库审计）；原文保存在 Git 历史（提交 `edfb5a9`）。逐项实验的预注册、数据和判定见
[实验索引](../research/EXPERIMENT_INDEX.md)。

除冻结 v2 的终测外，下文数字都来自**已暴露的开发集**（train150、dev100、heldout100），
是开发／回归证据，不是未见终测成绩。

## 一、做了什么

### 1. 记忆系统本体（8–9 月）

- 两阶段 LLM 事实抽取、去重、时间状态（新增／替换／终止／并存）、`as_of()`、来源追踪、
  原文按需恢复、REST 与 MCP 接口、多用户隔离、写者锁。
- **冻结 v2 终测**（LongMemEval-S 100 题，各方法一次）：LLTM v2 72%，naive RAG 65%，
  Full Context 86%；回答＋评分 token 比 naive RAG 少约 88%。
- LongMemEval-S 的 500 题已全部用于开发或终测，此后没有未见题。外部集 BEAM 在 9 月完成接入
  （切分、适配器、评分器、预注册），9 月 16 日因免费额度成本（约 12–18 个额度日）关闭。

### 2. 原文为主（9 月下旬）

记忆负责状态，问题直接在原始对话里检索 4,000 token 原话（v1）。heldout100：83/100，
对照多数票 69；train150：127/150，对照 98/150。之后的改进都以 v1 为对照。

### 3. 证据选择与程序计算线（10 月 1–4 日，grounded v1–v18）

回答前绑定来源、原话、数值和单位，求和／日期差由代码计算，长历史分页通读。
v15 选择机制验收 17/19（train150 已暴露题）。**v18 在 dev100 三次配对回归未通过**：
平均净 −3.33，多会话 −3.33；原因是它自己的引用核验在证据齐全时拒答（48 行中 24 行同轮 v1 答对），
回答调用约为 v1 的 3.6 倍。按注册，递归摘要成本实验未启动。

### 4. 分层诊断与改进（10 月 5–7 日）

- **错题分层**（dev100，零调用）：v1 的 26 道错题没有一道是检索漏找；23 道标准原话已在上下文，
  错在回答（时间推理 9、跨会话计数 5、知识更新 4 等）。
- **回答侧**：相对日期按对话日期换算并标注；"最近一次对话的值为当前值"；计数题和涉及日期、
  时长、先后的问题先逐条记下再作答。train150 设计外小探针：时间推理错题 0→5，计数／知识更新
  2→5，对照题只多错 1/12。关键发现：起作用的是"逐条记下"，单加日期标注只修好 1 道。
- **检索侧**（零调用）：同样 4,000 token，先装用户自己的话；问题里有"上周六／一周前"时按时间窗口
  先找。全部标准原话进入上下文：train150 78.1% → 90.4%，dev100 83.5% → 92.8%，heldout100
  86.0% → 93.5%。
- **产品**：原文为主接入 `AnswerEngine`（`ServiceConfig.raw_primary_tokens`，默认关闭），
  带跨用户隔离测试。本地记忆检索 p50 27 ms，含原文的上下文组装 p50 57 ms。
- **正式运行中**：v1、t3（回答侧改进）、t4（t3＋检索改进）在 heldout100 各跑 3 次
  （[预注册](../results/prereg-raw-primary-t3-t4-heldout100-v1.md)）。

## 二、存在的问题

| 问题 | 所在层 | 证据 | 换更强回答模型能否解决 |
|---|---|---|---|
| 生命周期几乎不触发：抽取器自由命名谓词，替代只在同一键内判断 | 时间键／生命周期 | 三库中被标为"替代"的事实 85–88% 同键下无旧事实；dev100 知识更新错题 4/4 出在记忆层 | 不能 |
| 证据没送到：跨多次对话的计数、带时间窗口的问题 | 检索 | train150 探针未修好的错题 9/10 证据不全 | 不能（检索改进已覆盖大部分） |
| 画像事实抽到了但检索不到（如年龄） | 检索 | dev100 `ba358f49` | 不能 |
| 回答读错、算错、选错 | 回答 | dev100 错题 23/26 证据齐全 | 部分（论文中 GPT-4o 只读标准证据也只有 87–92%） |
| 偏好没被抽成偏好记忆 | 抽取 | 21 道偏好题：9 道有普通事实在金标轮，12 道未抽到 | 部分（换抽取模型） |
| 记忆出处错位 | 写入 | dev100 3.8%，多为助手清单记忆 | 不能 |
| 评分有争议 | 评测 | 筛出 4 道确有争议 | 不能 |
| 没有未见评测集；单次运行噪声约 7 题 | 评测 | 500 题全部暴露 | 不能 |
| 免费额度与提供方 500/503 拖慢实验 | 运行 | v18 回归中评分调用失败率 43–47% | — |
| 研究证据与产品代码在同一仓库 | 工程 | `results/` 约占仓库物理行的 83%，`src/` 约 2.3 万行 | — |

## 三、接下来的计划

1. **完成 t3/t4 正式运行**，按注册判定：t4 − v1 ≥ +4、无题型 < −2、t4 中位上下文 ≤ 6,500；
   并读出回答侧、检索侧各自的贡献。
2. **修生命周期**：把孤立的"替代"事实链接到同主语、语义最近的旧事实（参照 Mem0 按相似记忆
   而非键名判定增改删），先离线验证"知识更新题当前记忆只剩新值"，再注册。
3. **画像常驻块**：年龄、职业、住址等少量画像事实不靠问题检索，常驻上下文（参照 Letta、Mastra）。
4. **强回答模型探针**：在 t4 之上用 Claude 或 GPT 跑约 20 题（花费约 1 美元），量出换模型的剩余空间。
5. **未见集终测**：恢复 9 月的 BEAM 适配器（提交 `3a050f5`），100K 切分已下载且与固定哈希一致；
   需要额度或付费层。
6. 偏好抽取改进、评分多模型投票加人工抽查、清单类记忆的出处定位。
