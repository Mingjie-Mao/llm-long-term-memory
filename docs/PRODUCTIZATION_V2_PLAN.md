# v2 产品化准入计划

这份计划只在 `test100` 一次性最终报告完成、实验结论固定之后执行。
它不是当前实验配置的一部分，也不能用来改变已经冻结的 v2 结果。

## 为什么要等实验结束

先确认“记忆系统确实有效”，再投入多人账号、安全和运维建设。否则可能把一个
效果还不稳定的实验原型包装成复杂但无用的服务。

## 实施顺序与完成标准

| 顺序 | 工作 | 通俗解释 | 完成标准 |
|---:|---|---|---|
| 0 | 产品化准入门 | 先决定实验结果值不值得上线 | v2 最终报告已生成；代码、配置和结果哈希可复核；已明确上线、继续实验或停止 |
| 1 | 身份认证与账号隔离 | 系统先确认“你是谁”，再只访问你的记忆 | `user_id` 从可信令牌取得而不是相信请求正文；跨账号读写、搜索、原文召回全部被拒绝；管理员权限单独定义 |
| 2 | 完整删除与数据导出 | 用户能拿走自己的数据，也能真正删除 | 一次请求可删除该用户的会话、原文、记忆、证据和向量；搜索不再返回；备份中的副本按保留期到期清除；可导出机器可读文件 |
| 3 | 备份与恢复 | 数据库坏了以后能够恢复，而不只是“有备份文件” | 自动加密备份；明确 RPO/RTO；在空环境做过恢复演练；恢复后的数据库、向量和用户隔离检查通过 |
| 4 | 费用与额度监控 | 知道每个账号用了多少模型请求和 token | 按账号、模型和操作记录请求/token；支持日/月上限和告警；没有可靠价格表时费用显示为空，不能猜美元金额 |
| 5 | 并发与幂等 | 多个请求同时到达时不重复写入、不损坏数据 | 写入有幂等键；同一会话并发更新有明确顺序；完成压力测试；若多进程写入则迁移到支持事务的共享数据库/向量后端 |
| 6 | 隐私与安全 | 尽量少保存敏感信息，密钥和日志不泄露内容 | 传输和静态数据加密；密钥不进代码/日志；日志默认脱敏；明确数据用途、保存期限、访问审计和安全事件流程 |
| 7 | 上线运维 | 出错能发现、能回退、能说明影响范围 | 健康检查、延迟/错误率/额度告警、版本指纹、灰度发布和回滚演练齐全；有服务目标和故障处理手册 |

## 必须通过的关键测试

| 类别 | 最少要证明什么 |
|---|---|
| 隔离 | 账号 A 即使猜到账号 B 的 memory/session ID，也读不到、改不了、删不了 |
| 删除 | 删除前可查到，删除后数据库、全文搜索、向量搜索和原文召回均查不到 |
| 恢复 | 从真实备份恢复后，行数、向量数、哈希关系和权限边界一致 |
| 费用 | 重试、失败和回退请求都正确计量，不重复收费，不漏记 token |
| 并发 | 重复提交只产生一份结果；并发更新不丢失、不交叉到其他账号 |
| 隐私 | 错误信息、结构化日志、指标和备份元数据不包含原始聊天或 API 密钥 |

## 暂不承诺

- 在单机 SQLite 上直接宣称支持多进程写入；
- 仅靠请求中的 `user_id` 作为真正鉴权；
- 把“软删除 memory 状态”说成用户数据已经彻底删除；
- 没有恢复演练就宣称备份可靠；
- 根据免费额度或过期价格猜测真实费用。

产品化完成后，README 中的“原型”定位才能重新评估。在此之前，v2 的实验指标
只说明测量集上的效果，不代表已经满足真实用户的安全和可靠性要求。
