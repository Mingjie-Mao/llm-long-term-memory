# 评测说明

本文是这个项目的评测口径：题集怎么切、指标怎么算、统计怎么读、最终结果是哪几个数字。
设计动机见[项目报告](PROJECT_REPORT.md)，实现细节见[架构说明](ARCHITECTURE.md)。

## 数据与切分

基准是 **LongMemEval-S**。选它而不是 LoCoMo 的理由是金标与评分器的可靠性：LoCoMo 的问题在
公开讨论中被反复指出，而本项目没有标注预算去逐题复核。

500 道题被切成五个互不相交的集合，**已经用尽**：

| 题集 | 用途 | 状态 |
|---|---|---|
| `dev50` | 第一批开发集：抽取提示词、门限、回退设计都由它决定 | 已烧掉 |
| `train150` | 检索权重、上下文形状等零调用扫描 | 可重复读 |
| `dev100` | 第二批开发集，2026-08-18 冻结 | 已用 |
| `test100` | v2 正式终测，**只跑一次** | 已用 |
| `heldout100` | 早期保留集 | 已用 |

`longmemeval_oracle.json` 带的是**同样 500 个问题**、不同的干扰材料，核对过而不是假定。
同一批问题换一堆干草不构成新数据，所以 **v2 之后的版本都没有新的未见终测**；后续数字属于开发或已暴露题集回归。
这是一个已声明的阻塞条件，不是脚注。

切分由 `split_dev_test(seed=0)` 按题型分层产生，确定可复现。

## 三个对照臂

历史 v2 终测比较以下三臂，使用同一个评分器。后续开发／回归按各自预注册选择对照；
本次原 test100 三轮回归只比较旧 v2 与限定范围 t4，没有重跑整段历史或 naive RAG。

| 臂 | 做什么 |
|---|---|
| `full_context` | 把整段历史塞进提示词。**参照点，不是天花板**——它也会因为太长而漏看 |
| `naive_rag` | 以**会话**为块取 top-5 |
| 本系统 | 结构化记忆检索 + 条件原文回退 |

另有显式 oracle 臂（直接注入金标事实），只作上限诊断，不参与任何headline 比较。

## 统计口径

- **配对比较，不比 headline。** 同一批题、同一个评分器，报告胜/负对数与**精确 McNemar** p 值，
  不只报百分比差。n=100 时，6 胜 0 负、8 胜 1 负或 10 胜 2 负才够 p < 0.05——这个下限在
  设计阶段就要算出来，否则会用一个本来就到不了显著的设计去否定一个真实效果。
- **重复三次再解读差异。** `eval repeat --runs 3`（最多 5）报告各次正确率、均值、样本标准差、
  实测极差和确定性 bootstrap 区间。已知噪声底：同一配置、同一库、逐字节相同的检索跑两遍，
  142 条探针里翻转了 38 条。任何小于这个量级的差都不能解读。
- **按命名空间聚类。** 同一个问题的多条记忆不独立，所以涉及记忆级计数的检验按命名空间聚类，
  设计效应取 `1 + (m−1)·ICC`。
- **延迟口径**：表里的 p95 是回答 provider 的 API 实测延迟，**不含等配额的时间**。小样本 p95
  是运行观测，不是"某策略更快"的结论。
- **评分器要审。** v1 阶段对 50 条独立标注的一致率是 94%，三处分歧里一宽两严。这支持
  "三处分歧没有观察到方向性偏差"，**不**支持"评分器无偏"或"LLM 标签就是真值"。

## 失败发生在哪一层

每个错答只分配**一个**首要原因，由 `lltm eval failure-audit` 产出工作表：

| 代码 | 含义 |
|---|---|
| E1 | 抽取丢失（再细分为数字、日期、时长、实体、事件、关系、否定） |
| E2 | 检索没召回 |
| E3 | 时间状态解析错误 |
| E4 | 上下文组装丢失 |
| E5 | 有证据但回答推理失败 |
| E6 | 评分器判错 |

### 四个诊断指标各自证明什么、不证明什么

| 指标 | 含义 | **不能**由它推出 |
|---|---|---|
| 来源会话召回 | 被选中的记忆引用了某个答案会话的 ID | 这条记忆里含有支撑答案的那个事实 |
| 结构化字面覆盖 | 金标字面出现在抽取出的记忆字段里 | 没逐字出现就等于答案无依据（派生答案不逐字出现） |
| 原文字面覆盖 | 金标字面出现在不可变的原始轮次里 | 最终措辞不在原文里就等于推不出来 |
| 端到端正确率 | 评分器判对 | 是哪一层导致了错 |

**"命中来源会话"不等于"关键事实进了上下文"**，这是整套诊断里最容易被读错的一条。98.3% 的
来源召回和 55.0% 的正确率之间那段差距，可以用来指导诊断，不能整段归因给回答合成。

## 最终结果

### v2 正式终测（`test100`，100 题，每臂一次）

| 方法 | 正确率 | 中位回答上下文 token | 回答＋评分实际 token |
|---|---:|---:|---:|
| v2 记忆＋条件回退 | 72% | **574** | 159,458 |
| 整段历史 | **86%** | 109,059 | 10,932,294 |
| naive RAG | 65% | 12,763 | 1,352,847 |

- v2 比 naive RAG 高 7 个百分点，但配对 **p = 0.3368**，不足以证明稳定优势。
- 整段历史比 v2 高 14 个百分点，**p = 0.0043**，这是一个真实的劣势，不回避。
- 上下文数字口径不同：记忆/RAG 是字符估算，整段历史用 provider 输入 token，所以约 190 倍、
  22 倍是**近似上下文比值**，不是账单承诺。usage 一列含回答与评分，不含共享抽取阶段的
  13,757,713 token。
- v2 的题型切片：`knowledge-update` **75.0%**、`temporal-reasoning` **74.1%**。
  同一 `test100` 上整段历史分别为 81.2%、88.9%；不能拿另一套 `dev50` 的 23.1%
  与这里的 74.1% 作配对比较。

### v3.3 验证（`dev60`）

冻结候选对 v2 对照：**55.0% vs 46.7%**，中位上下文 1,115 对 573，**p = 0.1797**。
有改进信号，不能写成稳定提升。这套题更难，也不是 `test100`，**55% 与 72% 不能排成版本曲线**。

### v4.2 引用式枚举（开发比较，**未晋级**）

计数题多数票对照 4/30、候选 5/30，净增 1，聚类 p = 1.0；注册的非计数方向门三层中两层为负。
87 条隐藏探针没有作答。结果按注册结论保留为 `not_promoted`。

后续发现原金标把记忆行数当成员数，可能把计划、偏好算成已完成行为。用模型建议的暂定叠加层重读
已付费行：对照 12/30、候选 7/30，描述性 p = 0.125。**这说明结论对金标敏感**，既不能用来证明
候选有害，也不能替换原注册结论。

### 原文为主 v1（回归级开发比较，**已暴露题集**）

在记忆上下文之外，按问题用 BM25 从整库原始轮次里取 4,000 token 原话一起给回答模型。
两套题都已暴露，数字是开发证据，不是未见终测，也不能接在 72% 后面排成版本曲线。

| 题集 | 对照 | 原文为主 | 配对胜/负 | 判定 |
|---|---:|---:|---:|---|
| `heldout100` | 69（4 次多数票；单次 70–73） | **83** | 18 / 4，净 +14 | `STOP`：中位上下文 5,598 超过注册上限 5,500 |
| `train150` | 98 | **127** | 32 / 3，净 +29 | `PASS`（中位总上下文 5,686，上限 6,000） |

两次都是单次运行，不宣称显著。之后的负结果：分页通读并逐条核验引用的 grounded v18 在
`dev100` 上每臂三次，平均 74.33 对 v1 的 77.67，净 −3.33，判 `FAIL`。

### t3／t4（`heldout100`，每臂三次，**已暴露题集**）

t3 在 v1 上加回答侧改动（相对日期换算、新值优先、计数和日期题先写笔记）；t4 再加检索侧改动
（用户原话优先、按问题里的时间窗口检索）。

| 臂 | 三次正确数 | 均值 | 中位总上下文 |
|---|---|---:|---:|
| v1 原文为主 | 82 / 81 / 80 | 81.00 | — |
| t3 | 87 / 86 / 87 | 86.67 | — |
| **t4** | 89 / 86 / 88 | **87.67** | 6,147 |

注册门全部通过：t4 均值净 +6.67（门槛 +4），无题型净值低于 −2，上下文 ≤ 6,500。
归因：回答侧 +5.67，检索侧 +1.00（未达 +2 的贡献门）。19 题上升、6 题下降，符号检验
p = 0.0146，不宣称显著。t4 现在是服务默认的回答方式。
[门判定](../results/analysis/raw-primary-t3-t4-heldout100-gate.md)

## 必须随结果一起读的限定

- **来源召回只表示命中至少一个金标会话**，不保证证据完整，更不保证答案事实没有在抽取时丢掉。
- **229 条合成探针**的 ground truth 由可读 store 的 SQL 推导，是诊断工具，不是外部基准，
  也不是未见终测。后续开发运行用的是 142 条子集，子集分数不能与整池分数直接比较。
- **v3.3 的 dev60 归档通过了当时实现的检查**，但后续审计发现 confidence 恒为默认值，
  九项门里有一项没有测到它想测的东西。归档保留，限定写在旁边；正确率与配对统计不受影响。
- **题型切片的分母可能很小**，用于定位失败，不能当作普遍提升的证据。
- **不做 SOTA 声明。** 这个项目的对照是自己的基线，不是排行榜。
