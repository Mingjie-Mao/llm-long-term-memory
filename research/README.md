# research/

本目录管理实验的**状态**，不是实验结果的第二份副本。数字始终以预注册、冻结包、逐题行和
`results/analysis/` 下的分析文件为准。

## 索引

[EXPERIMENT_INDEX.md](EXPERIMENT_INDEX.md) 是唯一入口：每条实验线的类型、状态、核心结论、
证据路径，以及**允许的下一步**。新增或改变一条实验线的状态时，改这份索引，而不是在别处再写一遍。

## active / archived 规则

本轮只建立规则和索引，**不批量移动历史文件**。移动一个实验的代码会使冻结包里记录的源路径
和摘要失效，而那正是冻结用来检测的东西；因此移动必须是一次有意的、单独验证过的操作。

- `research/active/` —— 允许继续运行或调参的实验线。进入条件：在索引中状态不是
  `STOP_*`、`not_promoted` 或“完成”。
- `research/archived/` —— 已得出结论、不再调参的实验线。**归档不等于删除**：负结果、失败和
  停止决策与通过的结果同样保留。

一条实验线迁入 `archived/` 前必须先完成：

1. 索引中状态、结论和“允许的下一步”已写清；
2. 冻结包、预注册和分析文件里引用到的源路径、哈希和文档链接全部更新；
3. 完整测试、Ruff 与 `public-demo/check_release_figures.py` 通过。

未满足这三条之前，实验线留在原位。索引说明它是什么，比目录名更重要。

## scripts/ 与 tools/ 的分工

两者都是研究工具，不是产品代码；产品代码只在 `src/llm_long_term_memory/` 下。

| 目录 | 内容 | 判据 |
|---|---|---|
| `tools/` | 可复现的实验 runner、离线门、分析器和冻结校验器 | 给定相同的已提交证据，输出应当逐字节可复现；写入 `results/` 的产物由它们生成 |
| `scripts/` | 人工与运维用的一次性脚本 | 依赖本机状态（store、data、凭据），不产出被引用的证据文件 |

跨工具复用的能力放在两个共享模块里，不要再复制一份：

- `tools/analysis_io.py` —— 读取 JSONL/JSON 证据、按题号建索引、文件摘要、同时写出报告的数据与正文；
- `llm_long_term_memory/stats.py` —— 精确 McNemar 与配对胜负分解。

一个 `tools/` 下的分析器如果输出随进程哈希种子变化，它就不是可复现的证据生成器。
曾经发生过一次：见索引的「已知复现缺口」。
